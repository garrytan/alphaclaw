# Design: Agent Administration (the "mega-alphaclaw-config" skill)
Generated by /plan-ceo-review + /plan-eng-review + /plan-devex-review on 2026-08-28
Branch: sun-valley-v2 | Repo: garrytan/alphaclaw
Implementation plan (full amendment history): ~/.claude/plans/system-instruction-you-are-working-keen-riddle.md

## Vision
The dashboard stops being *the* admin surface and becomes *one client* of a
manifest-described admin API. Admins administer the whole deployment — env,
channels, agents, cron, webhooks, models, upgrades, watchdog, team — by talking
to the OpenClaw agent, with tiers, audit, admin notifications, and one-time
confirm codes for dangerous ops. Containment reframing: the agent can ALREADY
curl the entire dashboard API with the SETUP_PASSWORD it inherits via
`gatewayEnv()`; this feature retires that unaudited, password-in-transcript
pattern and replaces it with a paved, tiered, audited road.

## Threat model (honest — do not soften)
As of v0.9.60, `gatewayEnv()` (lib/server/gateway.js) no longer spreads the full
`process.env` into the agent's shell: `filterGatewayChildEnv`
(lib/server/gateway-env-policy.js) applies an explicit allowlist with an
absolute deny list, so `SETUP_PASSWORD`, webhook/platform secrets, and
AlphaClaw internals are withheld from the OpenClaw child. This closes ENV
inheritance — the agent-admin tiers are now a real boundary against the agent
obtaining those secrets *from its environment*.

**Residual, not softened:** the child still runs as the same UID with
`HOME=kRootDir` and exec security `full` / ask `off`, so if exec is
unsandboxed it can read `kRootDir/.env` directly from disk. That is a
filesystem-level concern (sandboxing / file permissions), separate from env
inheritance, and this feature does not claim to close it. The auth layer still
exists to (a) keep secrets out of chat transcripts, (b) attribute actions
(`actor=agent`) for audit, (c) enable revocation, and (d) add tiered guardrails
+ structured errors. Break-glass `ALPHACLAW_GATEWAY_ENV_UNRESTRICTED=1`
(deployment env only) restores the legacy spread minus the absolute deny set.

## Architecture
```
 chat admin ─▶ OpenClaw agent ─▶ alphaclaw admin CLI (lib/cli/admin.js)
                                     │ Bearer <token from 0600 state-dir file>
                                     ▼
 Setup UI ─cookie─▶ Express /api ─▶ requireAuth (cookie | bearer[flag, opt-in])
                                     │  bearer ok → req.alphaclawActor = agent
                                     ▼
                     enforcement middleware (agent actor only)
                     manifest lookup → tier gate → confirm gate → redact res.json
                                     │  passed → req[Symbol grant] = frozen
                                     │           {opId, method, path, digests}
                                     ▼
                  requireAdmin (admin role, OR a grant matching this exact request)
                                     ▼
                  existing route handlers (validation, side effects, restart marking)
                       │                 │                    │
                 stores (.env,     watchdog.db audit    upgrade-notifier →
                 alphaclaw.json,   (agent_admin,        admin targets
                 openclaw.json)    two-phase)           (confirm codes, change notices)
 skill installer (agent-admin/skill.js) ◀ manifest + live state ▶ skills/alphaclaw-admin/SKILL.md
```

## Key components (as built)
- **Operation manifest** (`lib/server/admin-manifest/`): 22 domain modules, 220
  ops (0.9.76). Single source of truth for agent-facing POLICY (tier, redaction, docs,
  hints) — route handlers keep owning validation. Matching is on `req.baseUrl +
  req.path` (Express trims the mount prefix). A route-coverage test fails CI if
  any `/api` route is neither classified nor in `kUnmanifestedRoutes`.
- **Tiers**: safe / write / restart / dangerous / denied. `env.update` carries a
  body-aware `tierResolver` (setting a secret = restart; CLEARING one =
  dangerous). Descriptors also carry `readOp`, `async` metadata, `envelope`,
  `idempotent`, structured `params`, and `redactResponse`.
- **Bearer auth** (`routes/auth.js`): opt-in per call site (`allowBearer`) so
  ONLY Express `/api` accepts it — never WS upgrades or human cookie surfaces.
  sha256-before-timingSafeEqual; separate rate-limit scope from login (F2);
  lockout emits a watchdog event (F7). Distinct codes: `agent_admin_disabled` vs
  `agent_admin_unavailable` vs `unauthorized` (so a stale-skill agent never
  guesses or falls back to the password).
- **Token store** (`agent-admin/token-store.js`): 32-byte hex, 0600, state dir,
  never git-synced. Minted on flag-enable, removed on disable, rotatable
  (operator-only). mint failure surfaces in `/api/status.agentAdmin` and the
  skill (never a silently-dead bearer, F3).
- **Enforcement + redaction** (`agent-admin/enforcement.js`, `redact.js`):
  deny-outside-manifest for the agent actor across ALL of `/api` incl. GETs
  (never falls through to the gateway proxy, A20); two-phase audit (durable
  INTENT before self-restarting ops, OUTCOME via res `finish`/`close`, A26);
  redaction fails CLOSED. Agent-visible error text is sanitized after
  redaction (5xx → fixed sentence, 4xx → secret shapes/`token=`/control chars
  scrubbed; `code`/`hint` untouched). After the tier + confirm gate pass, the
  layer attaches an **enforcement grant** (`agent-admin/grant.js`): a frozen
  record under a module-private Symbol carrying opId, method, path and sha256
  digests of query and body. `requireAdmin` (routes/auth.js) admits the agent
  only with a grant that still matches the request — human sessions keep
  passing on role — so a route mounted without enforcement in front, a forged
  plain property, or a body rewritten after the grant fail closed (F067).
  Browse mutations resolve to `denied` for config/secret paths (F064/F066).
- **Confirm service** (`agent-admin/confirm-service.js` + `db/agent-admin/`):
  8-char base32 codes, plaintext in a 0600 DB so the dashboard can display them,
  10-min expiry, single-use atomic redemption, params-bound (method+path+query+
  body+context), dedup, attempt cap (3), backlog cap (10). Requires ≥1 admin
  target or dangerous ops return `no_admin_targets`.
- **Skill** (`agent-admin/skill.js` + `lib/setup/skills/alphaclaw-admin/`):
  generated from the manifest + slow-changing live state (masked admins,
  capability availability, release channel); regenerated at boot + on
  flag/token change; installed only when flag on AND token exists; last-good
  kept on transient build error; git-sync-excluded (renders masked PII).
- **CLI** (`lib/cli/admin.js`): out-of-process HTTP client, early-exit before
  the release-channel boot sync. `--data-stdin` keeps secrets out of argv;
  `--summary`; `--confirm`/`--context` headers; one-JSON-doc-on-stdout;
  `manifest` with live→static fallback.
- **UI** (`components/agent-admin-panel.js`): General-tab toggle, token rotate,
  next-session activation copy, pending-confirms chip.

## Static delta with the flag off
Only one: the `/api/admin` prefix is now a setup namespace (in
`SETUP_API_PREFIXES`), so it returns 404 from the setup layer instead of being
proxied to the gateway. Everything else is inert (no token, no skill, no stanza,
enforcement no-ops for cookie sessions).
