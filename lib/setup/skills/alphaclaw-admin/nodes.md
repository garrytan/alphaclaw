Controls the worker nodes (local or VPS) that can run the agent's exec and browser commands off the gateway, plus the exec policy that decides where and how commands run — the host (`gateway` vs `node`), the security mode (`deny`/`allowlist`/`full`), the ask mode, and the command-pattern allowlist that pre-approves specific commands. Gotcha: approving a pending node — or the device/pairing behind it — hands a remote machine the ability to execute on the operator's behalf, so treat every approval as dangerous and confirm the request out-of-band before granting it; removing a node revokes that access. Writing the exec config is restart-tier (it returns `restartRequired: true`) and won't take effect until the gateway cycles, whereas allowlist edits apply immediately. The connect-info endpoint's `gatewayToken` comes back masked for you — the pairing token is operator-only, so send the operator to Setup UI → Nodes to read it — and note that team/trusted-proxy mode disables token-based onboarding entirely.
