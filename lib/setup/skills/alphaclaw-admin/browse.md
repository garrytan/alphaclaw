The workspace file browser: read, write, create, move, delete, and download files under the workspace root, plus git-aware operations (per-file diff, restore, and a `git-sync` that runs AlphaClaw's shared sync engine — it commits only changed paths, merges with GitHub without rewriting the working tree, and answers 409 with a `code` (`lock_timeout`: another writer is busy, retry later; `merge_conflict`, `in_progress_operation`: hand it to the operator) instead of forcing anything). Everything is confined to the workspace root — paths are resolved server-side, so traversal outside the tree is rejected. Locked and protected paths (AlphaClaw-managed files, secret-bearing directories like `.alphaclaw/**`, credentials, and auth profiles) are enforced server-side and return 403 on write/create/move/delete — including moving or deleting an ANCESTOR folder that contains one, and the workspace root itself is never a mutation target (400) — so don't try to route around them. The manifest also DENIES (403 `denied`, no confirm) any read or mutation naming `openclaw.json`, `alphaclaw.json`, `devices/`, `.alphaclaw/`, credential stores, or an agent's `auth-profiles.json` — `../` spellings and `.bak` rotations included; use the dedicated ops (`env.*`, `models.*`, `team.*`) or hand it to the operator. Delete is recursive and dangerous-tier (expect a 428 `confirm_required`, then repeat with `--confirm <code>`); there is no trash or undo, so treat it as irreversible unless the file is git-tracked and recoverable via restore.
