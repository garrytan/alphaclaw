Team mode turns on named member accounts (email + password, invites, roles) so actions get attributed to a person instead of a single shared login. Treat this as attribution only — it is NOT a security boundary; anyone reaching the gateway directly can still claim a member identity.

Toggling team mode on or off is the dangerous operation: it transitions the gateway auth mode (snapshot -> trusted-proxy config -> restart -> identity probe, with auto-restore on failure), so the gateway restarts and in-flight requests drop. Members join through invites (`POST /api/team/invites` returns a one-time invite URL — a credential; relay it out-of-band, never into a shared transcript); role, display name and disabled state change per member via `PATCH /api/team/members/{id}`, removal is a `DELETE`, and any change that would leave no admin is refused with `409 last_admin`.
