Controls where admin alerts go: a preferred delivery channel plus the list of admin targets (channel + address pairs). These live in the non-synced state store, not `alphaclaw.json`, because the targets are PII. Gotcha: `preferredChannel` and every `adminTarget.channel` must be one of the store's supported channels (or `null` for the preference) — send anything else and the write is rejected with `invalid_setting`, not silently dropped, so read the current settings (or `supportedChannels`) before a PUT. Note that these same admin targets are where dangerous-op confirmation codes are delivered, so clearing or breaking them can leave you unable to confirm destructive operations.
