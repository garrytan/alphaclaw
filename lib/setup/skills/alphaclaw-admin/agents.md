Manages agent definitions, their channel bindings, and which one is the default. Each agent owns a workspace, and a binding is what routes a given channel account to that agent — set the default with `POST /api/agents/{id}/default`. With more than one agent OpenClaw has no implicit default: the default is recorded as `agents.defaults.systemAgent.agentId` (the system agent), and channels reach other agents only through bindings. Gotcha: deleting an agent goes through OpenClaw on the serving gateway and removes its bindings, cron jobs and files too (they move to OpenClaw's Trash); by default a snapshot of its chat history and workspace is kept first, and `snapshot=false` skips it. Read `GET /api/agents/{id}/delete-preview` before the DELETE, and prefer removing individual bindings when you only mean to re-route. A deleted agent's id stays reserved, so creating a new agent under it answers 409. Channel accounts (the `channel`/`accountId` a binding points at) are administered under channels (`/api/channels/accounts`), and adding one there already binds it to the `agentId` you pass — so create the account there first; the bindings routes here don't check that the account exists, and are for re-routing or narrowing (peer, guild, team) an account that is already configured.
