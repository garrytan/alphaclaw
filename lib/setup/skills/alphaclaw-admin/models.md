Controls which AI model the agent runs on — the default/primary model, its fallbacks, per-model settings, and thinking-effort options — plus the auth profiles that store provider credentials (each an `api_key`, `token`, or `oauth`, keyed by provider). Setting the model or writing model config is restart-tier: apply it, then tell the user a gateway restart is needed before it takes effect. Auth-profile secrets go via `--data-stdin`, never on the command line; API-key profiles stay synced with the matching provider env var, so a key set here also shows up under `env` (and vice versa).

**When a model will not run** ("⚠️ This model was not found", a watchdog notice naming a model, or a model you are asked to switch to): run `models.check.run` with `{"refs":["<provider/model>"]}` (omit `refs` to check every configured model) and read each result's `reason` and `fix`. The check asks OpenClaw whether the ref resolves and, for custom providers under `models.providers`, sends the provider one tiny request on the configured API, so `reason` quotes what the provider itself answered. Typical findings: the provider does not serve that id (pick an id it lists, or remove the ref from the allowlist), the provider serves it on the other OpenAI API (`openai-responses` instead of `openai-completions`, or back), the credential's env var is unset or refused, or no plugin provides the provider. `models.check.read` shows the last check and recent `model_not_found` failures. A `/model` choice turns off the configured fallbacks for that chat, so until the config is fixed tell the user to send `/model default` there. Never edit `models.providers` or the allowlist without the owner's go-ahead; those writes are restart-tier.
