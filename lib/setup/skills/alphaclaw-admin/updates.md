Controls OpenClaw upgrades: which release channel is selected (stable/beta/dev), which build is actually live, and the apply/rollback/mark-good/blocklist machinery around it. Read `GET /api/openclaw/channel` for the current channel and installed build before you touch anything. Gotcha: *selecting* a channel is just a catalog preference — it installs nothing, needs no restart, and returns `restartRequired: false` — but *applying* a build swaps the running gateway and restarts it, which ends your own session; treat apply and rollback as dangerous, final actions and warn the user first. Applying is long-running (`202` + `operationId`): poll the run ledger instead of trusting the 202, since the durable log outlives the restart. Every failure here comes back as the standard channel error envelope with a `code` and `hint` (see the error-codes table under How to call).
