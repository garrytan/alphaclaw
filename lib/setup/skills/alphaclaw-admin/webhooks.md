Named inbound HTTP hooks that receive payloads at `/hooks/<name>` (authed via `WEBHOOK_TOKEN` as a Bearer or `x-openclaw-token` header), optionally forward to a configured destination, and can expose an OAuth callback alias at `/oauth/<callbackId>`. Read endpoints also surface per-hook delivery health and the recorded request log. Gotcha: every mutation (create, update-destination, delete) runs `alphaclaw git-sync` and marks a restart as required, so changes are not live until the next restart — and the system-managed `gmail` hook is protected and returns 409 on delete. Transform-file conventions (the `transform.mjs` shape used to reshape payloads before forwarding) live in TOOLS.md.
