Read-only reporting on token and cost usage: a rolled-up daily summary plus per-session breakdowns and time series. The summary buckets by day, so pass a `timeZone` (or set the `x-client-timezone` header) to align day boundaries to the user's clock; it also defaults to the last 30 `days`. Gotcha: summary responses are cached for ~60s (see the `cached` flag), so usage recorded in the last minute may not appear yet — session and time-series endpoints are not cached. Sessions come back with derived labels (agent, Telegram, hook, cron) so you can attribute cost to the channel that drove it.
