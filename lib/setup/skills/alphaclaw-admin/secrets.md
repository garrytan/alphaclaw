The **secret drop** is how a key, token or password reaches this box without going through a chat. You ask for it by name; AlphaClaw returns a one-time link; the person opens it signed in to AlphaClaw as an admin, pastes the value into a masked box and presses Save. AlphaClaw writes the same value to its `.env` (the same write path as `PATCH /api/env`, so a restart is marked when the gateway's environment changes) and to OpenClaw's secret store (as a `secret` entry for a new name; an existing entry keeps its kind). You never see the value, and nothing about it is in the link.

Ask with `alphaclaw admin POST /api/secrets/requests --data '{"name":"GITHUB_TOKEN","reason":"open pull requests"}'` and send the person the returned `url` exactly as returned. The link works once, for 15 minutes, and only in a browser signed in to AlphaClaw as an admin: anyone else who sees it can do nothing with it. Names are uppercase (`A-Z`, `0-9`, `_`, starting with a letter); reserved, deployment-only, locked (`ALPHACLAW_GATEWAY_LOCKED_ENV`, for example `WM_GUARDS_*`), Channels-managed and launcher keys are refused when you ask and again on Save. An AlphaClaw restart drops open links; ask again.

Afterwards `GET /api/secrets/requests/<id>` gives `status` (`pending`, `stored`, `partial`, `expired`, `partial_expired`), `stores` (`env`, `store`: which hold it) and `reach.env`: `gateway_env` (the gateway gets it after a restart the person chooses; offer it, do not restart on your own), `next_gateway_start` (OpenClaw loads it from its `.env` at its next start) or `never` (only scripts that read `.env`). AlphaClaw also tells the admins by name when a drop is stored. Confirm to the person by name only: "Stored GITHUB_TOKEN."

A multi-line value (a PEM key) goes to OpenClaw's secret store only, because `.env` holds one line. A `partial` drop wrote one store; the link stays open until it expires so the person can retry.
