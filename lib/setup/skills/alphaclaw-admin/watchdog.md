The watchdog supervises the AlphaClaw gateway process: read its health/status, recent events, log tail, and live resource usage — memory, CPU, disk, processes, event loop lag — via `GET /api/watchdog/resources`, tune supervision settings, and trigger a repair when it's wedged. Machine capacity and the settings tuned from it live in the autotune domain. `POST /api/watchdog/repair` relaunches the gateway (channels drop briefly; in-flight work is interrupted) — use it only when status shows the gateway actually down or stuck. Settings updates touching `notificationsEnabled` or `notificationsVerbose` escalate to dangerous-tier (expect a 428 `confirm_required`, then repeat with `--confirm <code>`); `autoRepair` alone is a plain write. An overseer review with no `incidentId` is a situation report over the live log and escalates to dangerous-tier (428, then `--confirm <code>`); re-reviewing a settled incident by id is a plain write. `terminal/*` endpoints are operator-only (denied for you). Memory-monitor settings (`PUT /api/watchdog/memory`): arming `autoRestart` is dangerous-tier; `budgetMb` (operator RSS cap in whole MB above the current usage, or null for the derived cap) and `maxRestartsPerDay` (auto-restart brake, 1–24) are ALWAYS dangerous-tier (expect a 428, then `--confirm <code>`) — they decide how soon and how often the gateway restarts.
